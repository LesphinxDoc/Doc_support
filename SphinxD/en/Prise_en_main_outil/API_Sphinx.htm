Sphinx API

To access the list of Sphinx APIs, proceed as follows:

  1. Click on your account name (top right).

  2. Click on API - Developers.

    To add an API access token, please click here.

    Three types of methods can be used:

    • GET : To retrieve information/data

    • DELETE : To delete data

    • POST : To add/modify items/data

Below are the different API functions available:

Diffusion

  • GET : List all campaigns : Returns all broadcast campaigns for an account.

  • GET : Get campaign information : Returns data about the given campaign such as its name, number of recipients, associated study, and distribution links, etc.

  • POST : Copy a campaign : Copies the structure of a campaign from a source study to another with options, and returns general information on the created campaign.

  • GET : List all sends : Returns the list of sends for the specified campaign.

  • GET : List all recipients : Returns all recipients and the current response status for each of them.

  • POST : Add a recipient : Creates a new recipient and adds them to the campaign.

  • DELETE : Delete recipients identified by email address or phone number for a given campaign.

  • DELETE : Delete a recipient by ID : Removes the specified recipient from the campaign, as well as all tracking data related to their activity.

  • GET : List blacklisted emails or phone numbers : Returns the list of emails and phone numbers in the blacklist.

Studies

  • GET : List all studies : Returns the list of studies for an account and, for each study, information such as its name or number of responses.

  • POST : Create a study : Creates a blank study. Opening and closing dates can be optionally defined. System variables are automatically added (key, entry date, ...).

  • GET : Get study information : Returns the details of the specified study.

  • DELETE : Delete a study : Removes the specified study and its associated resources (data, images, campaigns, web reports, ...).

  • POST : Copy a study : Copies a study, possibly with responses, and returns general information about the created study.

  • GET : Export responses to a JSON or CSV file : Returns the study responses in a JSON or CSV (';' delimiter) stream: variable names, labels, and raw data.

  • POST : Add or update responses : Adds new responses to the study or updates the data if records already exist (depending on the value of the "key" variable).

  • DELETE : Delete a set of responses : Removes one or more responses identified by their key. The API assumes the request body contains the list of keys to delete.

  • GET : Get a link to an observation : Creates a temporary link targeting the specified form for a specific observation specified by a key.

  • GET : List all report links : Returns all links to web reports, as well as the study preview link.

Variables

  • GET : List all variables : Returns the variables of the study, their type and their characteristics.

  • POST : Create a variable : Creates a new variable in an existing study.

  • GET : Search for a variable by name : Returns the specified variable of a given study, its type and its characteristics.

  • DELETE : Delete a variable : Removes an existing variable from a study. Note that this operation also deletes all existing responses to this question.

  • PUT : Update text and option labels : Updates text and option labels for a variable in an existing study.

    Note that options are relevant only for closed variables.

Analysis Views

  • GET : List all views : Returns the list of all analysis views for a given study.

  • POST : Copy a view : Copies an analysis view.

  • GET : Get a link to a view : Creates a temporary link targeting the specified analysis view.

    You can optionally specify a sample parameter to filter the data and process only part of the total sample.
